시작하기

상태 최신 · 담당 개발 · 마지막 갱신 2026-11-20

찾아라 도깨비의 모든 문서를 모은 곳이에요. 지금 게임의 기준은 feature/game-feel 브랜치예요.

웹에서 보기: https://azlsh-web.github.io/FindDokkaebi/docs/ (공개). 웹 게임은 https://azlsh-web.github.io/FindDokkaebi/에 있어요.

역할별로 먼저 볼 문서

나는 먼저 볼 문서
기획자 결정 기록 → 대사 트리 → 대사 수정표
아트팀 아트팀 전달사항 → 아트 구조
사운드팀 사운드팀 전달사항 → 게임 플로우
개발 (처음 온 사람) 아키텍처 → 문서 도구 → 마일스톤

폴더 구조

Docs
├─ 0_시작하기.md     이 문서
├─ 1_기획            게임이 어떻게 동작하는가 (GDD)
├─ 2_제작            언제 무엇을 하는가, 왜 그렇게 정했는가

├─ 4_기술            코드와 그림의 구조, 문서 도구 (TDD)
└─ 5_QA와_기록       검증 결과, 지난 기록 (보관)

모든 글 문서는 맨 위에 상태 · 담당 · 마지막 갱신을 적어요. 상태는 세 가지예요. - 최신: 지금 게임과 맞아요. - 검토 필요: 게임이 바뀌어서 다시 봐야 해요. - 보관: 지난 시점의 기록이에요.

자동이라고 적힌 문서는 코드에서 다시 만들어서 늘 최신이에요.

기획

게임이 어떻게 동작하는지 적은 문서예요.

문서 만드는 법 내용
게임 플로우 자동 흐름도와 경우별 화면 사진 전체
대사 트리 · PDF 자동 모든 대사와 화면 글자를 흐름 순서대로
연출 기획 사람 화면별 연출과 그렇게 정한 이유

제작

일정, 할 일, 결정과 그 이유를 적은 문서예요.

문서 만드는 법 내용
마일스톤 사람 지금 구현 상태와 앞으로 할 일
결정 기록 사람 기획서와 달라진 점(C-01~), 협의할 것
백로그 사람 지금 작업 뒤에 할 일 (저장소의 BACKLOG.md)

전달

다른 팀에 보내는 문서예요. 받은 사람이 바로 쓸 수 있게 써요.

문서 만드는 법 받는 곳 내용
아트팀 전달사항 자동 아트팀 필요한 그림, 크기, 파일 이름
사운드팀 전달사항 자동 사운드팀 화면별 소리, 파일 이름과 느낌, 우선순위, 파일 규칙
대사 수정표 자동 기획자 모든 대사에 번호를 붙인 표. 바꿀 대사만 적어 돌려줘요

기술

코드와 그림이 어떻게 짜여 있는지, 문서를 어떻게 만드는지 적은 문서예요.

문서 만드는 법 내용
아키텍처 자동 코드 구조, 판정 흐름, 도구, 자주 하는 수정
아트 구조 자동 게임 그림 전체를 화면 → 오브젝트 → 파일 트리로
문서 도구 사람 문서 갱신, 대사 수정 받기, 자동 테스트, 문서 사이트

QA와 기록

검증 결과와 지난 기록이에요. 보관 문서는 지난 시점의 결과라서 지금 화면과 다를 수 있어요.
