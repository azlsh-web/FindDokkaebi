완료한 일 - [x] A1 · A2 · A4 · A5 · A6 · A7: C-56 흐름. 사탕 · 도깨비 하트 대신 주인공 하트 3개, 요청 물건은 고르면 빼앗김, 맞설 물건은 쪽지를 들이밂, 배드 엔딩 삭제. 결정 기록 - [x] B2: 5챕터 판정 대기는 초록 도깨비가 찾아다니는 화면 대신 빛나는 쪽지와 흑화 도깨비로 바꿈. - [x] C2: 하트가 깎일 때 튀고 흔들리는 효과. - [x] C3: 그리는 동안 흑화 도깨비가 쪽지 곳곳에서 나타났다 사라지고, 도깨비불 · 낙서 · 붉은 막이 움직임. 터치와 그림 · 판정은 그대로 통과함. - [x] C4: 하트 0이면 친구가 화면 안쪽으로 쓰러지고, 영혼이 떠올라 도깨비에게 날아가 사라짐. - [x] 쪽지를 들이밀면 도깨비가 움찔한 뒤 판정 대기로 넘어감. 사탕 먹기 · 쪽지 읽기는 없음.

A. 이야기가 안 맞는 곳 - [ ] A3. 주인공이 맞설 물건을 어떻게 아는지 설명이 없어요. 지금도 "무서워한댔어"라는 혼잣말뿐이고, 친구는 서 있기만 해요. 누가 언제 알려 줬는지와 친구의 역할을 정해요.

B. 그림이 안 맞는 곳 - [ ] B1. 흑화 도깨비(회색 몸 · 갈색 머리)와 대사 상자 얼굴(초록 · 노란 머리)이 달라요. 흑화한 뒤에도 대사 상자에는 귀여운 얼굴이 나와요. - [ ] B3. 점프스케어 얼굴(Scare_Face)도 그림체가 달라요. - [ ] B5. 해피 엔딩은 "도망갔네"인데 도깨비가 그대로 서 있어요. - [ ] B7. 게임오버에서 도깨비가 사람 더미 옆에 작게 서 있어요. 기획서에서는 도깨비 등 뒤에 쌓여 있어요. - [ ] B9. 고르기 카드가 흰 카드예요. 다른 화면은 쪽지 질감이에요.

B5 · B7과 같이 처리해요. - [ ] 쪽지에서 물건이 튀어나오는 연결 연출: 지금은 쪽지를 들이밀고 빛나는 판정 대기를 거친 뒤, 결과 화면에서 물건이 커지며 등장해요. 쪽지에서 물건으로 이어지는 움직임은 별도로 없어요.

코드 정리 (2026-11-20, 마감 뒤에)

파일 나누기(partial class)는 끝났어요. 아래는 데이터 파일 · 씬 · 메뉴 · 문서 도구가 함께 바뀌어서 마감 뒤로 미뤘어요.

  • Stage/Ch 이름 섞임 정리 : 물건 데이터는 StageData인데 챕터 구조에서는 "물건"이에요. ItemData로 바꾸려면 .cs 파일 이름과 .meta를 같이 옮기고, 필드는 [FormerlySerializedAs]로 이어 줘야 데이터가 안 날아가요. 데이터 파일 이름(Stage1_Bat 등)과 테스트 그룹 이름(stage1~stage5)도 같이 정해요.
  • Mvp 접두어 빼기 : 에디터 도구 이름 · 메뉴 · flag 파일 이름 · 문서가 함께 바뀌어요.
  • MvpSceneBuilder.Build() 쪼개기 : 1,300줄 함수 하나에 지역 변수 274개가 얽혀 있어요. 화면별 함수로 나눌 때는 "다시 조립한 씬이 ID만 빼고 같은지" 비교로 확인해요.
  • 테스트 기록: 예전 chapter5 단독 실행의 방망이는 한 화면에 하나만 : c5_happy 실패는 11/21 변경 후 단독 테스트 75개에서 재현되지 않았어요. 현재 미해결 오류로 세지 않아요.
