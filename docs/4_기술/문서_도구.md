# 문서 도구

> **상태** 최신 · **담당** 개발 · **마지막 갱신** 2026-11-22

문서를 다시 만들고, 대사 수정을 받고, 문서 사이트를 올리는 방법이에요. 문서 경로는 모두 `Tools/docs/paths.py` 한 파일에 모여 있어요. 문서를 옮기거나 이름을 바꾸면 이 파일만 고쳐요.

## 문서 갱신

보통은 커밋 훅이 문서를 갱신해요. 사진을 새로 찍어 확인할 때만 아래 명령을 실행해요. AI 판정은 보내지 않아요. Unity가 켜져 있어야 사진이 찍혀요. 약 6분 걸려요. 커밋 직전에 같은 명령을 다시 실행할 필요는 없어요.

```bash
python Tools/docs/update_docs.py --shots
```

- **자동 문서:** 게임 플로우(흐름·물건 표·사진을 한 문서로), 판정·그림 대응표와 그림 비교, 대사 트리, 대사 수정표, 요청 현황, 아트팀 · 사운드팀 전달사항, 아키텍처, 아트 구조.
- **문서가 게임과 어긋나면:** 도구가 멈추고 알려 줘요. 예를 들어 소리 이름을 코드에서 바꾸고 요청 목록을 안 고치면 멈춰요.
- **자동으로 안 되는 것:** 연출 기획, 마일스톤, 결정 기록, 이 문서, 아키텍처 설명 글(`Tools/docs/make_arch_doc.py`)은 사람이 판단해서 고쳐요. 링크로 공유한 페이지도 다시 올려야 해요.
- **Python:** 그림 라이브러리(Pillow)가 있는 Python으로 실행해요. 이 컴퓨터에서는 `python`이 msys64 쪽을 먼저 찾을 수 있어서, 안 되면 `py`나 `Python313\python.exe`로 실행해요.

### 커밋할 때 자동으로 하기 (켜야 동작해요)

아래 설정을 켜면 게임 파일이 바뀐 커밋에서 위 명령이 자동으로 실행되고, 다시 만든 문서가 그 커밋에 함께 들어가요. 저장소마다 한 번만 켜면 돼요.

```bash
git config core.hooksPath .githooks
```

| 바뀐 것 | 자동으로 하는 일 |
|---|---|
| 게임 코드, 씬, 그림, 단계 데이터, 글꼴 | 같은 파일 내용으로 찍은 사진이 있으면 재사용. 없으면 새로 찍고 자동 문서 갱신 (약 6분) |
| 소리 파일, 문서 스크립트와 데이터 | 사진 없이 문서만 다시 만들기 (약 1분) |

Unity가 꺼져 있거나 Play 중이면 경고만 하고 이전 사진을 그대로 써요.

문서를 만들기 전에 `Tools/hooks/check_commit.py`가 먼저 규칙을 확인해요.

| 확인하는 것 | 어기면 |
|---|---|
| 게임 코드(`Assets/Scripts`, `Assets/Editor`의 `.cs`)가 바뀌었으면, 그 코드로 돌린 **전체 테스트가 PASS**인지 (`Temp/SelfTest/result.txt`) | 커밋을 막아요. 급하면 `SKIP_TEST_CHECK=1 git commit ...` |
| 씬 파일(`.unity`)이 바뀌었는데 씬 조립 도구는 그대로인지 | 경고만 해요 (씬을 손으로 고쳤을 수 있어요) |

부분 테스트 결과로는 통과하지 않아요. 게임 코드를 바꿨다면 커밋 전에 전체 테스트를 한 번 돌려요. 문서·설정만 고친 커밋에는 게임 전체 테스트를 다시 요구하지 않아요.

사진 재사용은 촬영 완료·오류 0개·모든 원본 사진 존재와 게임 파일의 SHA-256 기록을 확인해요. 파일 삭제·이름 변경·내용 복원도 감지해요. 전체 테스트와 화면 사진은 검증 목적이 달라 각각 한 번 실행하고, 손으로 사진을 찍은 뒤 훅이 또 찍는 중복을 줄여요.

### 요청 목록 갱신

`Tools/docs/request_data.py`가 요청 현황과 팀 PDF 두 개의 공통 목록이에요. 받은 그림의 출처는 `art_tree_data.TREE`, 현재 물건은 `Assets/Data`, 소리 파일 이름은 `Sfx.cs`와 대조해요. 새로 받으면 출처·신규 목록을 갱신하고 아래 명령을 실행해요.

```bash
python Tools/docs/make_requests.py
```

파일이 존재한다고 자동으로 받음이 되지는 않아요. 임시 파일과 수령 기록을 따로 관리해요. 이름·경로가 목록과 다르면 생성기가 멈춰요. 옛 `apply_art_zip.py`는 종이 그림 5장 전용이며 신규 목록 전체를 넣는 도구가 아니에요.

## 대사 수정 받기

기획자에게 [대사 수정표](../3_전달/대사_수정표.xlsx)를 보내고, 돌려받은 파일을 아래 명령으로 검사한 뒤 반영해요. 반영하면 대사 트리와 수정표도 새로 만들어져요.

```bash
python Tools/docs/apply_dialogue_edits.py 받은파일.xlsx
```

```bash
python Tools/docs/apply_dialogue_edits.py 받은파일.xlsx --apply
```

## 자동 테스트

Unity 에디터가 켜져 있으면 `Temp/mvp_selftest.flag` 파일을 만드는 것만으로 테스트가 돌아요.

- 파일에 그룹 이름을 적으면 그 그룹만 돌려요. 비워 두면 전체예요.
- 결과는 `Temp/SelfTest/result.txt` 마지막 줄에 나와요 (`[SelfTest] 전체 PASS (n개)`). 화면 사진도 같은 폴더에 찍혀요.
- 작업 중에는 고친 곳의 그룹만 돌리고, 전체는 커밋 전에 한 번 돌려요.
- Unity 창이 뒤에 있으면 늦게 시작할 수 있어요. 요청 파일이 사라지면 시작된 거예요.

## 문서 사이트

[판정·그림 대응표](../2_제작/판정_그림_대응표.md)와 [그림 비교](../2_제작/판정_그림_비교.html)는 사이트의 **제작** 목록에 있어요. 현재 판정을 받는 17개 물건의 94가지 조합을 보여 줘요. 기준이나 그림을 바꾸면 Unity에서 물건 데이터를 반영한 뒤 `py Tools/art_temp/build_judge_variant_manifest.py`, `py Tools/art_temp/build_judge_variant_review.py` 순서로 갱신해요. 일반 문서 갱신에도 이 두 도구가 포함돼요. 사이트 생성기는 대응표에서 참조하는 그림을 함께 복사하므로, 공개 사이트에서도 그림이 보여요.

**주소:** <https://azlsh-web.github.io/FindDokkaebi/docs/> (공개). 웹 게임은 한 단계 위인 <https://azlsh-web.github.io/FindDokkaebi/>에 있어요.

- **올리기:** `feature/game-feel`에 `Docs` 폴더가 바뀐 커밋을 푸시하면 GitHub Actions(`.github/workflows/docs-site.yml`)가 몇 분 안에 다시 만들어 `gh-pages`의 `docs/` 폴더에 올려요. 웹 게임 파일은 건드리지 않아요.
- **만드는 도구:** `Tools/docs/make_docs_site.py`. 내 컴퓨터에서 미리 보려면 `python Tools/docs/make_docs_site.py`를 실행하고 `Temp/DocsSite/index.html`을 열어요.
- **목록:** 사이트 홈의 카드는 [시작하기](../0_시작하기.md)의 구역별 표에서 읽어요. 새 문서는 그 표에 한 줄 넣어야 설명과 함께 나와요. 표에 없는 파일은 카드 이름만 나와요.
- **옛 주소:** 폴더를 바꾸기 전 주소(`전달/아트.pdf` 등)로 들어와도 열리게, 사이트에 옛 주소를 남겨요. 목록은 `paths.py`의 `LEGACY`예요. 통합한 옛 게임 플로우·대사 트리 PDF 주소에는 작은 이동 안내 PDF만 둬요 (`PDF_REDIRECTS`).
- **Docs 밖 문서:** 저장소 맨 위의 `BACKLOG.md`는 사이트에서 "제작 → 백로그"로 보여요. 목록은 `paths.py`의 `EXTERNAL_PAGES`예요.
