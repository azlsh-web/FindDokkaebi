## 일하는 규칙

이전 계정 기억에 있던 사용자 요청을 정리했어요. 원본 파일은 `인수인계/기억/`에 있어요.

- **기획 변경은 먼저 묻기.** 기획서를 존중하고, 기획이 바뀌는 일은 합의한 뒤 반영해요. 반영하면 `5_기획_변경_기록.md`에 번호를 붙여 기록해요.
- **AI 판정을 마음대로 보내지 않기.** 실제 Gemini 판정(`/judge` POST)은 사용자가 허락한 횟수만큼만 보내요. 무료 사용량이 적고, 그 사용량은 사용자의 플레이와 녹화용이에요. 확인은 `/health` · `/models` · `LocalJudge` 테스트로 해요.
- **설명하지 말고 보여 주기.** 화면 제목, 설명 글, 다음으로 넘기는 전용 버튼을 만들지 않아요. 대사 터치, 그림, 움직임으로 진행해요. 버튼은 진짜 선택이 필요한 곳에만 둬요. 움직임은 잔잔하게 하고, 캐릭터가 공중에 뜨거나 화면 밖으로 나가지 않게 해요.
- **아트 요청은 꼭 필요한 것만.** 다시 오리기, 코드로 그리기, 있는 그림 재사용으로 되는지 먼저 봐요. 요청을 줄이자는 추천은 사용자에게 확인한 뒤 반영해요.
- **대사를 바꾸면 엑셀도.** `GameScript.cs`를 고치면 `update_docs.py`로 대사 수정표(`Docs/전달/14_대사_수정표.xlsx`)와 대사 트리를 다시 만들어요.
- **게임이 바뀌면 문서도.** 위의 [커밋 전에 할 일](#커밋-전에-할-일)을 지켜요. Unity가 꺼져서 사진을 못 찍었다는 경고가 나오면 숨기지 말고 알려요.
- **시안은 부품처럼.** 시안은 한 흐름으로 이어 붙이지 말고 단계별 페이지와 화면별 보드로 나눠, 하나씩 눌러 볼 수 있게 만들어요.
- **웹 배포는 사용자가 시킬 때만.** gh-pages 맨 위는 웹 게임이고, 문서는 `docs/` 폴더에 있어요. 배포할 때 `docs/` 폴더를 지우지 않아요.
- **문서 사이트.** 새 문서는 `Docs/0_문서_안내.md`의 표에 넣어야 사이트에 나와요.

## 이번에 할 일

사용자가 2026-11-12에 준 목록이에요. 정해진 것과 아직 물어봐야 할 것을 나눠 적었어요. 1번과 3번은 기획 변경이라서 `5_기획_변경_기록.md`에 C-23부터 기록해요. 11월 11일에 정한 돋보기 규칙(초콜릿 2개)은 이번 결정으로 바뀌어요.

### 1. 간식과 돋보기 규칙 바꾸기

- **초콜릿을 없애요.** 맨 위 줄, 이야기 종료의 초콜릿, `chocolatesPerStage`, 테스트, 문서에서 모두 빼요. 받은 초콜릿 그림은 `ArtSource/원본/미사용`으로 옮겨요.
- **사탕은 다시 단계마다 3개**예요 (`candiesPerStage` 2 → 3). 쪽지를 건넬 때마다 1개씩 써요.
- **돋보기는 게임 전체에서 1번**만 쓸 수 있어요.
  - **1단계에서 적절한 때에 쓰는 법을 보여 줘요** (사용자 답). 그리고 게임 전체에서 1번만 쓸 수 있다는 것도 대사로 알려 줘요. 처음 메모에는 "첫 실패 때 대사로 알려 주자"고 적혀 있었어요.
- **무료 기회:** 한 단계에서 **2번째로 틀렸을 때, 단계마다 1번** 무료로 돋보기를 쓸 기회를 줘요. 무료로 받았다는 느낌이 나게 애니메이션으로 보여 줘요 (예: 도깨비가 돋보기를 건네주고, 맨 위 줄로 날아가 반짝이기). 그래서 실제로는 "전체에서 1번"보다 더 많이 쓸 수 있게 돼요.
- **3초 안내와 카운트다운:** 지금은 누르자마자 렌즈가 열려요. 3초만 볼 수 있다는 걸 알려 주고, 보는 동안 남은 초를 보여 줘요 (3 · 2 · 1. 떠올리기 화면의 숫자 모양을 다시 써도 돼요).

### 2. 5단계 대사: 주인공이 친구를 잃어버렸다

- 지금은 도깨비가 "큰일이야, 네 친구가 길을 잃었나 봐!"라고 말해요 (`GameScript.cs` 70번째 줄 근처). 주인공이 뭐든 잘 잃어버리는 설정이니, **주인공이 친구를 잃어버렸다**는 쪽으로 바꿔요.
- 대사는 **Claude가 초안을 써서 게임에 넣고**, 대사 수정표 엑셀로 기획자가 확인해요.

### 3. 이야기 종료와 챕터 선택

- **사탕 통:** 이야기 종료에서 아낀 사탕은 사탕 전용 통에 모아서 보여 줘요. 통 그림은 아직 없어요. Claude가 임시로 만들고, 사용자가 보고 별로면 아트팀에 요청해요.
- **끝 대사:** 지금은 "소풍 즐거웠지? 처음으로 돌아갈까?" 뒤에 처음 화면으로 돌아가요 (`GameScript.EndingAsk`, `GameManager` 783번째 줄 근처). 이걸 "다음에 또 뭐 잃어버리면 또 올게" 같은 대사로 바꾸고, **챕터 선택 화면**으로 넘어가요.
- **챕터 선택 화면 (새 화면):** 시작 화면에서 `게임 시작하기`를 누르면 챕터 5개가 떠요. 지금은 **소풍 챕터만** 있어요. 나머지 4개는 **자물쇠와 `준비 중`** 으로 보여 줘요 (사용자 답). 이야기 종료 뒤에도 이 화면으로 와요.

### 4. 일시정지 버튼을 소리 설정으로

- 오른쪽 위 일시정지 버튼을 **배경음 · 효과음 볼륨 설정**으로 바꾸고, 아이콘도 알맞은 것으로 바꿔요.
- 창을 **열면 지금처럼 게임이 멈춰요** (향 · 관찰 시간, `Time.timeScale = 0`). 사용자 답이에요.
- 배경음 4곡은 아직 없어요. 효과음은 `Sfx.cs`에서 나와요.

### 5. 대사 줄바꿈

- "그려 줘." 같은 대사가 줄 끝에 걸리면 두 번째 줄에 `줘.`만 남아요. 지금은 단어 하나만 안 쪼개지게 하고 있어요.
- 마지막 줄에 짧은 조각 하나만 남지 않게 해요. 예를 들어 "그려 줘"처럼 붙어 다니는 어절을 `<nobr>`로 묶거나, 줄 길이를 고르게 나눠요. 모든 대사를 대사 상자 크기로 확인해요. 자동 테스트에 검사를 넣으면 좋아요.

### 6. 5단계 색 섞기: 같은 색을 여러 번 누를 수 있다는 걸 알려 주기

- 5단계(세 가지 색 섞기)에서는 같은 색을 여러 번 눌러 비율을 바꿀 수 있다는 걸 알려 줘야 해요.
- 대사로만 알려도 되고, 대사가 나오는 동안 위쪽 실제 색 섞기 창에서 시범을 보여 줘도 좋아요. 예를 들어 빨강 2 · 노랑 2 · 파랑 1로 갈색을 만들어 보여 줘요. 이건 테스트에 있는 조합이에요.

### 7. 그리기 화면 UI 크게 바꾸기

- 휴대폰에서 그림 그리는 곳이 너무 좁다는 피드백을 받았어요. 크게 바꿔야 해요.
- **먼저 배치가 다른 시안 2~3개**를 화면별 보드로 보여 주고, 사용자가 고른 뒤에 만들어요.
- 그림판 크기(지금 512×604)가 바뀌면 판정에 보내는 그림, `LocalJudge`, 빈 쪽지 검사, 채점표까지 영향을 받아요. 크기를 바꾸는 시안이면 그 점을 함께 적어요.

## 시작 전에 물어볼 것

위에서 정해지지 않은 것들이에요. 작업 전에 사용자에게 물어요.

1. **돋보기 시범의 "적절한 때"는 언제인가요?** 1단계 첫 그리기 중에 도깨비가 보여 주는지, 1단계에서 처음 틀렸을 때인지 정해야 해요. 시범으로 쓴 것이 "전체 1번"을 써 버린 것으로 치는지도 정해야 하고, 1단계를 한 번에 맞히면 어떻게 되는지도 정해야 해요.
2. **무료 기회를 안 쓰고 그 단계가 끝나면** 사라지나요, 다음 단계로 넘어가나요? 전체 1번 돋보기를 아직 안 쓴 상태에서 무료 기회가 생기면 2번 쓸 수 있나요?
3. **볼륨 설정은 저장할까요?** 게임을 다시 켜도 유지할지(PlayerPrefs), 시작 화면이나 챕터 선택 화면에서도 열 수 있게 할지 정해야 해요.
4. **챕터 선택 화면 그림:** 지금 있는 그림(쪽지, 카드, 배경)으로 Claude가 꾸밀까요, 아트팀에 요청할까요? 소풍 챕터 칸에는 무엇을 보여 줄까요?
5. **작업 순서:** 마감(11/15)까지 사흘이에요. 7번(그리기 UI)은 가장 크고 위험해요. 추천 순서는 이래요: 1 · 2 · 5 (규칙과 대사, 다른 작업의 바탕) → 3 · 4 (새 화면) → 6 → 7은 시안을 일찍 보여 주고 고르는 대로 진행. 사용자가 원하는 순서가 있는지 물어요.
6. **웹 배포와 main 머지:** 이번 작업이 끝나면 누가 언제 하나요? (이전에는 배포를 다른 세션이 맡았어요.)
