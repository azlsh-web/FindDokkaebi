1단계 방망이 · Unity 6.3 LTS · 씬 1개 + 패널 6개 + 스크립트 3개 · 판정은 테스트 입력(체크박스)

1. 플레이 흐름 (GameManager 의 State)

화면을 바꾸는 방법은 하나뿐입니다: ShowPanel(패널) — 그 패널만 켜고 나머지 5개는 끕니다.

2. 구성 요소와 의존 관계

화살표 방향 = "누가 누구를 아는가". DrawingBoard 와 StageData 는 GameManager 를 모릅니다. 그래서 각각 따로 고치거나 재사용하기 쉽습니다.

3. 데이터 흐름 — 그림 한 장이 결과가 되기까지

단계어디서 → 어디로무엇이 전달되나
게임 시작Stage1_Bat.asset → GameManagerstage 칸에 연결된 데이터 전체 (이름, 이야기, 그림 2장, 특징 3개)

4. 결과 계산 규칙 (ShowResult)

맞힌 특징 수결과도깨비가 가져오는 것버튼
3 / 3성공진짜 방망이 (originalSprite)내 그림과 비교하기
1 ~ 2 / 3부분 성공엉뚱한 방망이 (wrongSprite)다시 그리기 (간식 남으면) · 포기하고 비교
0 / 3실패아무것도 없음다시 그리기 (간식 남으면) · 포기하고 비교
간식은 3개로 시작, 제출할 때마다 1개. 0개면 다시 그리기 버튼이 사라지고 "간식이 다 떨어졌어요" 표시.

5. AI 판정으로 바꿀 때 — 바뀌는 곳은 한 군데

// 지금 (MVP, 테스트 입력)
public void OnJudgeConfirmed()
{
    bool[] present = new bool[3];
    for (int i = 0; i < 3; i++)
        present[i] = featureToggles[i].isOn;
    ShowResult(present);
}
// 나중 (AI 판정)
byte[] png = board.Texture.EncodeToPNG();
// → 프롬프트 + png 를 LLM 에 전송
// ← {"features":[{"featureId":"F1",
//      "status":"present"}, ...]}
present[i] = (status == "present");
ShowResult(present);   // 그대로 재사용
기획서 6장의 JSON 구조(inputStatus, features[].status)를 받아 bool[] 로만 바꿔주면 결과·재도전·비교 화면은 손대지 않아도 됩니다.
